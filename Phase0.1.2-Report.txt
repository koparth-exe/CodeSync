5. CORRECTIONS MADE
================================================================================

All ten specific corrections required by the prompt were meticulously enacted:

1. Correction 1 — GitHub Authentication:
   - Primary: GitHub App + OAuth Device Authorization Flow requesting fine-grained
     repository `Contents: write` permissions restricted strictly to user-selected
     repositories.
   - Monolithic `repo` and `public_repo` scopes are explicitly documented as
     rejected security anti-patterns.
   - PAT is documented strictly as an advanced manual fallback with clear warnings
     regarding lack of built-in repository isolation and indefinite lifetimes.

2. Correction 2 — Storage Architecture:
   - Hybrid partitioned storage architecture is fully documented:
     * `browser.storage.local`: settings, credentials, queue metadata, lease record,
       strictly budgeted to stay under 1 MB.
     * `IndexedDB (codesync_db)`: full source-code payloads (`payloads` store) and
       long-term synchronization history (`history` store), solving the 10 MB quota limit.

3. Correction 3 — Queue Concurrency & Lease Model:
   - Documented two-tier concurrency architecture:
     * Tier 1: W3C Web Locks API (`navigator.locks.request`) for active runtime
       context mutual exclusion.
     * Tier 2: Persistent `QueueLeaseRecord` with Probe-and-Verify protocol,
       30-second TTL, 10-second heartbeat, 5-minute maximum lease cap, stale lease
       recovery, crash counter incrementing, and 3-crash poison-pill isolation.
   - Rejection of Compare-And-Swap assumptions on `browser.storage.local` is explicit.

4. Correction 4 — GitHub Write Semantics:
   - Replaced all descriptions of the multi-request HTTP write workflow as "atomic"
     with "validated transactional write protocol with optimistic concurrency control".
   - Preserved all 10 steps: repository identity, branch integrity, canonical path,
     content UTF-8, token freshness, existing blob SHA resolution, duplicate hash
     evaluation, safe PUT write, conflict handling, and post-write commit verification.
   - Explicitly stated that the overall multi-request workflow is NOT a single atomic
     database transaction.

5. Correction 5 — 409 Conflict Handling:
   - Fully documented the 8-Step Conflict Protocol:
     409 -> halt write immediately -> cache-busting re-fetch GET -> extract remote
     SHA & size -> download & compute normalized SHA-256 hash -> re-evaluate
     duplicate policy -> conditionally write only if explicitly permitted (max 2
     revalidation passes) -> otherwise preserve remote content and surface conflict
     via `REQUIRES_ATTENTION` with side-by-side diff UI.
   - Blind retries of an identical PUT are categorically prohibited.

6. Correction 6 — Extraction Confidence vs Security Trust:
   - Explicitly decoupled Extraction Confidence (quality/completeness heuristic, 0.0–1.0)
     from Security Trust & Authenticity (deterministic validation).
   - Invariant enforced: Passing confidence (>= 0.70) MUST NEVER authorize a GitHub write.
   - Low confidence (< 0.70) fails closed to User-Assisted Recovery.
   - High confidence (>= 0.70) merely qualifies payload to enter the 9-Step
     Deterministic Validation Pipeline (submission ID, accepted status, platform enum,
     slug regex, bijective language mapping, code size, SHA-256 match, origin boundary,
     safe path grammar).

7. Correction 7 — Extraction Architecture:
   - Platform-specific extraction hierarchy documented: API -> Authenticated Endpoint ->
     Submission Page HTML -> World Bridge Fetch/XHR -> Editor Extraction -> DOM Fallback ->
     User-Assisted Recovery.
   - Universal network interception explicitly rejected.
   - Platform adapters specified: LeetCode (GraphQL + Editor bridge), Codeforces
     (Public API + HTML parse), CodeChef (API status endpoint), GeeksforGeeks
     (polling API + ACE bridge).
   - Codolio confirmed as DEFERRED (aggregator/tracker profile).

8. Correction 8 — Path / Unicode Security:
   - Documented Three-Pillar Path Architecture:
     1. Canonicalization (multi-pass URL decode, NFKC folding, separator normalization,
        null-byte rejection).
     2. Strict Safe Path Grammar (POSIX portable ASCII regex `^[a-zA-Z0-9_.-]+$`,
        categorical rejection of all non-ASCII Unicode/confusables/homoglyphs,
        whitespace, control chars, null bytes, DOS reserved names CON/PRN/AUX/NUL/COM).
     3. Base Repository Folder Boundary Validation.
   - Invariant enforced: "Canonicalization reduces ambiguity; validation determines
     acceptability." NFKC normalization alone is not a security barrier.

9. Correction 9 — Competitor Analysis:
   - Purged all unsupported blanket claims ("every competitor is single-platform /
     PAT-only / DOM-fragile").
   - Grounded CodeSync differentiation in verified technical capabilities: least-privilege
     GitHub App, layered extraction, persistent WAL queue, validated transactional
     write protocol, optimistic concurrency control, 8-step 409 conflict revalidation,
     three-pillar path grammar, cross-browser MV3 architecture, and local-first privacy.

10. Correction 10 — ADR Summary:

9. REMAINING RISKS
================================================================================

1. Platform Web Surface Drift: Competitive programming platforms periodically
   update their DOM class names and submission modals.
   *Residual Risk Level*: Low.
   *Mitigation*: The layered extraction architecture prioritizes authenticated APIs
   and Monaco editor bridges over DOM selectors. If all layers fail or confidence
   drops below 0.70, the system fails closed into User-Assisted Recovery.

2. Browser Service Worker Suspension Dynamics: Background service workers in MV3
   can be suspended after 30 seconds of inactivity.
   *Residual Risk Level*: Low.
   *Mitigation*: The Write-Ahead Log (WAL) in IndexedDB ensures submissions survive
   suspension, and the persistent lease record recovers incomplete items upon alarm wakeups.

3. GitHub App Initial User Onboarding: The Device Authorization Flow requires users
   to enter an 8-character user code on github.com.
   *Residual Risk Level*: Low (UX only).
   *Mitigation*: The extension Options UI automatically opens the authorization page
   and copies the code to the user's clipboard for seamless onboarding.
