5. SECURITY FINDINGS
================================================================================
The Phase 0 architecture audit uncovered several critical security vulnerabilities
and architectural risks in the initial design:
1.  Excessive GitHub Scope: Phase 0 relied on OAuth App requesting monolithic `repo`
    scope. This granted blanket read/write access to all public and private repos,
    pull requests, and settings, violating least privilege.
2.  Storage Quota Vulnerability: Storing full source code payloads in `browser.storage.local`
    risked hitting the 10 MB quota during offline queuing, risking silent data loss.
3.  Path Traversal Exposure: The initial path sanitization was insufficient against
    encoded traversal (%2e%2e%2f), double encoding, Unicode homoglyphs, and DOS reserved
    names (CON, PRN, AUX, NUL).
4.  TOCTOU Write Races: Creating files without optimistic SHA checks risked silent
    overwrites if concurrent tabs or user manual commits modified the target file.
5.  Poison Pill Crash Loops: If a malformed submission crashed the ephemeral service
    worker, restarting the worker could induce an infinite crash-restart loop.
6.  Brittle Network Claims: Stating that network interception was the universal
    mechanism overlooked platforms with public REST APIs (Codeforces) or internal
    GraphQL polling (LeetCode), while raising unnecessary permission concerns.

================================================================================
6. ARCHITECTURAL FINDINGS
================================================================================
1.  Ephemeral Background Lifecycle: Chromium MV3 service workers terminate after ~30s
    of idle time. All state transitions must follow a Write-Ahead Log (WAL) before
    triggering network requests.
2.  Browser Namespace Parity: WXT v0.21.x cleanly abstracts the `browser.*` vs `chrome.*`
    namespace differences without custom wrapper overhead.
3.  Storage Partitioning: A hybrid model separating metadata (`storage.local`) from
    payloads (`IndexedDB`) preserves fast service worker boot time while scaling to
    thousands of solutions.
4.  Codolio Boundary: Codolio is a portfolio aggregator, not an online judge. Creating
    an adapter for it would be an architectural error.

================================================================================
7. DECISIONS MADE
================================================================================
1.  GitHub App Architecture Adopted: User access tokens via Device Flow with repository-level
    scoping and 8-hour expiration. PAT demoted to manual fallback.
2.  Hybrid Storage Adopted: `browser.storage.local` for settings/metadata/locks + `IndexedDB`
    for source code payloads and sync history.
3.  Deterministic 8-Step Path Canonicalization Adopted: Multi-pass URL decode, NFKC
    normalization, null-byte rejection, segment whitelisting, and base-folder boundary checks.
4.  10-Step Safe Write Pipeline Adopted: Optimistic locking with remote SHA verification,
    409 conflict handling with backoff, and content-hash deduplication.
5.  Platform-Specific Extraction Hierarchy Adopted: Safest feasible layer per platform;
    confidence threshold enforced at 0.70; fail-closed User-Assisted Recovery fallback.
6.  Distributed TTL Mutex Adopted: 30-second TTL lock in `storage.local` with heartbeat to
    serialize queue draining across concurrent tabs.
7.  Poison-Pill Quarantine Adopted: Items causing 3 service worker crashes are isolated
    into `REQUIRES_ATTENTION`.
8.  Strict Content Security Policy Adopted: `script-src 'self'; object-src 'none'; base-uri 'none'; frame-ancestors 'none';`.
9.  Zero-Telemetry Policy Re-affirmed: Absolute ban on third-party telemetry, tracking,
    or logging of credentials and source code.
10. Fail-Closed Principle Enforced: All ambiguous states halt execution rather than
    attempting best-effort writes.

9. THREAT MODEL SUMMARY
================================================================================
Documented in docs/SECURITY.md §3. Evaluates 26 distinct threat scenarios:
- A: Malicious coding-platform webpage (Zod schema validation, no credentials in DOM).
- B: Malicious page content/script injection (Origin verification, strict IPC schemas).
- C: Compromised platform API response (Zod parsing, 500 KB payload cap, safe defaults).
- D: Malicious repo/path input (Regex whitelist, 8-step canonicalization pipeline).
- E: Malicious metadata (Control char stripping, HTML entity decoding, integer checks).
- F: Token theft (Storage in extension storage.local only, zero web/script exposure).
- G: Token leakage in logs (Custom Logger with automated token/secret redaction).
- H: Compromised extension context (Content script holds zero tokens and zero storage write access).
- I: Malicious extension messages (Strict sender.id === runtime.id, external messages disabled).
- J: Replayed messages (UUID v4 nonce and 30s timestamp window verification).
- K: Duplicate submissions (SHA-256 line-normalized hash comparison; skip commit).
- L: Concurrent queue processing (Distributed mutex lock with 30s TTL in storage.local).
- M: GitHub SHA race conditions (Remote SHA optimistic check, 409 retry with backoff).
- N: Repository confusion (Repository identity snapshotted at enqueue time).
- O: Branch confusion (Explicit branch existence validation before write).
- P: Path traversal (Rejection of .., leading slashes, absolute paths).
- Q: Encoded traversal (Multi-pass decode, NFKC normalization, null-byte rejection).
- R: XSS in UI (React 19 auto-escaping, zero dangerouslySetInnerHTML, strict CSP).
- S: DOM injection (Toasts use Shadow DOM and textContent only).
- T: Prototype pollution (Object.create(null), immutable configuration dictionaries).
- U: Supply chain compromise (Minimal dependencies, package-lock pinning, npm audit in CI).
- V: Malicious extension update (2FA on releases, store developer security, no remote code).
- W: Browser-specific differences (Standardized WXT abstraction, ephemeral reconciliation).
- X: Source code disclosure (Zero telemetry, HTTPS-only directly to api.github.com).
- Y: Excessive permissions (GitHub App least privilege: Contents: write on select repos).
- Z: Queue abuse / DoS (Max 200 items, 500 KB per item, rate limit backpressure).

10. GITHUB SECURITY DECISION
================================================================================
- Architecture: GitHub App using Device Authorization Flow for user-to-server tokens.
- Permissions: Repository `Contents: write` only. Zero access to issues, PRs, or admin.
- Repository Isolation: User selects "Only select repositories" during app authorization.
- Token Lifetime: Access tokens expire in 8 hours; automatic rotation via 6-month refresh tokens.
- Revocation: User disconnect wipes tokens and calls GitHub revocation endpoint.
- PAT Policy: Supported strictly as an advanced/manual fallback with prominent warnings.
- Write Safety: 10-step safe pipeline with optimistic locking, SHA conflict handling, and rate limit backpressure.

================================================================================
11. STORAGE DECISION
================================================================================
- Architecture: Hybrid Partitioned Storage.
- `browser.storage.local` (<1 MB used): Stores user settings, auth tokens/metadata,
  queue metadata (`QueueItemMetadata`), and distributed locks (`codesync:queue:lock`).
- `IndexedDB` (`codesync_db`): Stores source code payloads (`QueueItemPayload`) and
  full sync history (`SyncHistoryEntry`).
- Rationale: Eliminates the risk of exceeding the 10 MB `storage.local` quota while
  ensuring rapid service worker startup without deserializing large source code blobs.

================================================================================
12. QUEUE SECURITY DECISION
================================================================================
- Protocol: Two-phase Write-Ahead Log (WAL) — payload written to IndexedDB, metadata
  written to storage.local before network operations begin.
- Concurrency: Distributed mutex with 30-second TTL lock and heartbeat.
- Crash Recovery: Startup reconciliation detects interrupted tasks, increments crash counter.
- Poison-Pill Isolation: Submissions causing 3 service worker crashes are isolated to
  `REQUIRES_ATTENTION`.
- Retry Engine: Exponential backoff with ±20% jitter; maximum 5 attempts for transient errors.
- Quota Management: Capped at 200 items; 500 KB max source code size per item.

================================================================================
13. EXTRACTION ARCHITECTURE DECISION
================================================================================
- Hierarchy: Ordered by safety and feasibility (Public API -> Same-Origin Authenticated
  Endpoint -> Detail Page HTML -> Editor Bridge -> Scoped DOM -> User-Assisted Recovery).
- Universal Interception Rejected: Platform adapters implement only viable methods:
  - LeetCode: Same-origin GraphQL API + submission check polling + Monaco bridge.
  - Codeforces: Public REST API (`user.status`) + submission page HTML parsing.
  - CodeChef: Submission API observation + submission detail API.
  - GeeksforGeeks: Submission payload interception + editor state bridge.
- Confidence Threshold: Submissions with confidence < 0.70 fail closed and trigger
  User-Assisted Recovery.
- Codolio Status: Confirmed deferred. No adapter created (aggregator, not a judge).

15. REMAINING RISKS (DEFENSE-IN-DEPTH RESIDUAL RISKS)
================================================================================
1.  Platform DOM/API Drift: Coding platforms may change their internal APIs, GraphQL
    schemas, or DOM layouts without notice. (Mitigation: Layered extraction fallbacks,
    fail-closed behavior, User-Assisted Recovery, and automated CI canary tests).
2.  Host Browser Sandbox Flaws: If the browser extension sandbox or underlying OS is
    compromised by malware, local storage can be inspected. (Mitigation: OS-level profile
    encryption, 8-hour token lifespans).
3.  GitHub API Downtime: Extended GitHub outages or rate-limit exhaustion. (Mitigation:
    Persistent 200-item queue survives restarts; pauses processing until rate limit reset).
4.  Token Revocation Latency: If a user revokes access on GitHub.com, the extension
    discovers this on the next write attempt. (Mitigation: Pre-flight token validation,
    immediate transition to REQUIRES_ATTENTION, zero corrupted commits).
