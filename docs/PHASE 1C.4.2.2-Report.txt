### 2. Root Architecture Integration

The completed end-to-end submission-to-GitHub pipeline operates as follows:

```
Platform Adapter (LeetCode, CodeForces, CodeChef, GeeksforGeeks)
      ↓
Validated Extension Message (UUID v4 nonce, sender tab verification)
      ↓
Service Worker Trust Boundary (validatedBy: "SERVICE_WORKER")
      ↓
Durable WAL / IndexedDB Queue (PENDING state, immutable TargetSnapshot)
      ↓
QueueDrainer Trigger (submission_event, startup, alarm)
      ↓
QueueManager.drainQueue(...)
   - Web Lock ("codesync:queue_drain")
   - Durable Lease + Fencing Token
   - Poison Pill & Crash Check
   - Atomically transitions item: PENDING/FAILED → PROCESSING
      ↓
Real QueueItemHandler (GitHubQueueSyncHandler)
   - Untrusted metadata validation (validatedBy, UUID, platform, SHA-256)
   - Payload existence & max byte bounds check (≤ 100 KB)
   - Recalculated SHA-256 hash strictly matches persisted metadata hash
   - TargetSnapshot validation (immutable repository, branch, base folder)
   - Path resolution & canonicalization via Three-Pillar Path Engine
   - Safe commit message sanitization (NFKC, control char stripping, 200 char cap)
   - Dispatches to GitHubContentsService.synchronizeFile(writeOptions)
      ↓
GitHubContentsService (Existing Phase 1C.2.1 Implementation)
   - Credential Lifecycle & Token Refresh
   - Authoritative Remote Branch & Repo Validation
   - Remote State Pre-flight GET
   - Duplicate Policy Evaluation (REPLACE_IF_DIFFERENT, KEEP_ALL, SKIP_IF_EXISTS)
   - Atomic PUT / Tree Write + OCC
   - Immediate Post-Write Verification GET
      ↓
Typed Result / Structured Error Mapping
   - created / updated → status: "completed" (commitSha, commitUrl)
   - skipped_identical / skipped_exists → status: "skipped"
   - Rate Limit → status: "failed", retryable: true, resetTimestamp / retryAfterSeconds
   - Auth / Conflict / Forbidden / Not Found / Malformed → status: "requires_attention"
   - Uncertain Write Outcome → status: "requires_attention" (never marked completed)
      ↓
QueueManager updates queue record
   - COMPLETED: records commitSha, completedAt, moves payload to History
   - FAILED: increments attempts, schedules nextRetryAt = max(exponentialBackoff, rateLimitDelay)
   - REQUIRES_ATTENTION: records lastError, quarantines item safely
      ↓
Zero Direct Queue State Mutation from Handler
```

- Recalculated SHA-256 hash is computed via `computeContentHash(normalizeSourceCode(payload.sourceCode))`.
- If the recalculated hash does not match `item.contentHash`, the write is aborted fail-closed and escalated to `requires_attention` with `ErrorCode.INVARIANT_VIOLATION`.

### 13. Retry / Rate-Limit Behavior

- The handler never sleeps, loops, or reschedules retries internally.
- On `GitHubRateLimitError`, the handler extracts `resetTimestamp` and `retryAfterSeconds` from the error and returns them inside `SyncResult.error`.
- `QueueManager` receives this error and calculates:
  ```ts
  const backoffDelay = calculateBackoff(item.attempts);
  const rateLimitDelay = item.lastError?.resetTimestamp
    ? Math.max(0, item.lastError.resetTimestamp - Date.now())
    : (item.lastError?.retryAfterSeconds ?? 0) * 1000;
  item.nextRetryAt = Date.now() + Math.max(backoffDelay, rateLimitDelay);
  ```
- This ensures rate-limit reset deadlines are strictly respected and never preempted by short exponential delays.

---

### 14. Uncertain-Write Behavior

- If `GitHubContentsService` encounters a timeout, network disconnect, or dropped connection after dispatching a PUT request, it throws `GitHubWriteOutcomeUnknownError`.
- The handler catches `GitHubWriteOutcomeUnknownError` and maps it to `status: "requires_attention"` (`ErrorCode.GITHUB_WRITE_OUTCOME_UNKNOWN`).
- The item is quarantined in `REQUIRES_ATTENTION` state. It is **never** marked completed and **never** blindly re-executed with duplicate PUTs.

---

### 15. Verification Behavior

- `GitHubContentsService` performs an authoritative GET verification after write dispatch.
- If verification is `CONFIRMED`: commitSha and fileSha are returned to `QueueManager`, which persists `commitSha` and `completedAt`.
- If verification is `FAILED`: an error is thrown and mapped to `requires_attention`.
- If verification is `UNKNOWN`: `result.status` is set to `requires_attention` (`verificationStatus: "UNKNOWN"`). The handler preserves the commitSha if available, marks `status: "requires_attention"`, and never marks the item as synchronized.

---

### 16. Idempotency Behavior

- Queue item deduplication and identity hierarchy are maintained:
  - If `submissionId` exists: `platform + submissionId` is authoritative.
  - Distinct submission IDs with identical source code produce distinct queue items and are never collapsed.
- Target repository duplicate policy (`REPLACE_IF_DIFFERENT`, `KEEP_ALL`, `SKIP_IF_EXISTS`) is evaluated downstream at GitHub write time, cleanly decoupled from submission identity.

---

### 17. History / Diagnostics Behavior

- On successful synchronization (`completed`), `QueueManager` moves payload metadata to IndexedDB `History` store:
  - `submissionId`, `platform`, `problemSlug`, `problemTitle`, `language`, `status`, `commitSha`, `timestamp`.
- Full source code is **not** duplicated into history.
- Redaction utilities scrub tokens, cookies, and secrets from all logger outputs.
- Diagnostics and error messages never include tokens (`ghp_`, `Bearer`), cookies, or raw source dumps.

---

### 18. Security Boundary Verification

- **Direct Invocation Protection**: Neither `createGitHubQueueItemHandler` nor `GitHubQueueSyncHandler` is attached to `globalThis` or exported to page contexts / content scripts.
- **Service Worker Trust Boundary**: Any queue item without `validatedBy === "SERVICE_WORKER"` is immediately quarantined with `ErrorCode.INVARIANT_VIOLATION`.
- **Fencing Protection**: A stale background worker whose lease has been superseded by a higher fencing token is rejected fail-closed with `StaleLeaseError` when attempting queue mutations.
- **Fail-Closed Target/Path Rejection**: Hostile path traversal, malicious repo strings, or forged parameters fail closed before any GitHub network call.
