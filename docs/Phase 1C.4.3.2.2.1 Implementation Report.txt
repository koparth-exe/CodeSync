## 9. Security Validation

1. **Mutation Authority vs Start-of-Operation Lease:**
   - In `FENCE-INT-03`, Worker A possessed valid lease authority when claiming the queue item into `PROCESSING` at line 433.
   - However, when Worker A's handler finished (failing mid-flight), its authority had been superseded by Worker B ($1 \to 2$).
   - The test proves that `validateFencingToken` at line 549 strictly evaluated *current* authority at the mutation boundary, aborting fail-closed and preventing stale error persistence.
2. **Token Recycling Defense:**
   - In `FENCE-INT-02`, even though Worker B received the same numeric token (`1`) following Worker A's orderly release, Worker A's stale attempts failed because authority verification requires exact matching of the tuple `(workerId, fencingToken, expiresAt)`.
3. **No Production Backdoors:**
   - All failure injections and interleavings utilized existing test-only hooks (`onBeforeCommit`, `onBeforePreFlightGet`) without modifying production source code or weakening security checks.
