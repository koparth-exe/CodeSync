2. **Firefox Behaviors Proven vs. Unproven:**
   - **Proven in Real Firefox (Gecko MV3):**
     - **Manifest V3 Acceptance (`RB-INSTALL-02`):** Gecko engine accepted the MV3 manifest, verified gecko ID `codesync@extension.local`, `strict_min_version: "128.0"`, and `background.scripts: ["background.js"]` without schema errors via WebDriver BiDi.
     - **Event Page Startup (`RB-STARTUP-02`):** Background browsing context initialized cleanly, creating Gecko profile storage (`storage/default/moz-extension+++<uuid>/`).
     - **Storage & IndexedDB Durability Across Restart (`RB-PERSIST-02`):** Browser process was terminated (`kill()`) and restarted on the same persistent profile directory. On-disk SQLite database files (`idb/*.sqlite`) remained intact across the shutdown/relaunch boundary.
     - **Webpage Privilege Isolation (`RB-SECURITY-02`):** Untrusted web pages navigated in Firefox cannot access `browser`, `chrome.runtime`, or extension storage.
   - **Unproven in Real Firefox (with Justification):**
     - **Service Worker Termination:** Firefox MV3 utilizes event pages (`background.scripts`), not service workers (`background.service_worker`); WebDriver BiDi lacks per-worker thread stop controls. Process-level restart was proven via `RB-PERSIST-02`.

     - **Web Locks Contention (`RB-LOCKS-01`):** Standard W3C `navigator.locks` supported natively in Gecko 96+; browser-agnostic logic proven in Chromium real-browser tests.
