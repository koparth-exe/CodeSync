## 7. Fresh Worker Verification

The harness does **NOT** simply call `new QueueManager()` inside a retained execution context.

Instead, [createCrashTestEnvironment](file:///d:/Parth/Projects/CodeSync/tests/helpers/crash-harness.ts#L241) simulates a genuine browser Service Worker lifecycle boundary:
1. **Shared Durable Media**: [MemoryStorageDriver](file:///d:/Parth/Projects/CodeSync/tests/helpers/e2e-harness.ts) (`chrome.storage.local`) and [MemoryPayloadStorageDriver](file:///d:/Parth/Projects/CodeSync/src/shared/storage/indexeddb.ts) (IndexedDB) persist across worker instances, while [MockGitHubApiServer](file:///d:/Parth/Projects/CodeSync/tests/helpers/mock-github-api.ts) maintains persistent remote GitHub state.
2. **Worker Context Isolation**: Calling `env.createWorker(label)` instantiates a completely disjoint graph of production services:
   - Dedicated [TerminableStorageDriver](file:///d:/Parth/Projects/CodeSync/tests/helpers/crash-harness.ts#L53) wrapping the shared storage
   - Dedicated [StorageService](file:///d:/Parth/Projects/CodeSync/src/shared/storage/local.ts)
   - Dedicated [TerminablePayloadDriver](file:///d:/Parth/Projects/CodeSync/tests/helpers/crash-harness.ts#L100) wrapping shared IndexedDB
   - Dedicated [PayloadStorage](file:///d:/Parth/Projects/CodeSync/src/shared/storage/indexeddb.ts)
   - Dedicated [QueueConcurrencyManager](file:///d:/Parth/Projects/CodeSync/src/shared/queue/concurrency.ts)
   - Dedicated [QueueManager](file:///d:/Parth/Projects/CodeSync/src/shared/queue/manager.ts)
   - Dedicated [GitHubApiClient](file:///d:/Parth/Projects/CodeSync/src/shared/github/client.ts)
   - Dedicated [GitHubContentsService](file:///d:/Parth/Projects/CodeSync/src/shared/github/contents-service.ts)
   - Dedicated [QueueDrainer](file:///d:/Parth/Projects/CodeSync/src/shared/queue/drainer.ts)
   - Dedicated [SubmissionHandler](file:///d:/Parth/Projects/CodeSync/src/shared/adapters/submission-handler.ts)
3. **Hard Context Termination**: When Worker A crashes or is discarded (`workerA.terminate()` / `env.discardWorker(workerA)`), its `storageDriver` and `payloadDriver` are flagged `terminated = true`. Any subsequent read or write attempt by Worker A throws [ProcessTerminatedError](file:///d:/Parth/Projects/CodeSync/tests/helpers/crash-harness.ts#L42), ensuring stale Worker A code cannot leak mutations into durable storage.
4. **Explicit Reference Inequality**: The test suite explicitly asserts that Worker B retains zero in-memory references to Worker A:

## 8. Durable State Verification

Worker B reloads state authoritatively from storage:
1. **Startup Drain Trigger**: Worker B invokes `workerB.queueDrainer.drain("startup")`, replicating the production `chrome.runtime.onStartup` event handler in [src/entrypoints/background.ts:L33-L41](file:///d:/Parth/Projects/CodeSync/src/entrypoints/background.ts#L33-L41).
2. **Reconciliation from Storage**: [QueueDrainer.drain](file:///d:/Parth/Projects/CodeSync/src/shared/queue/drainer.ts#L46) delegates to [QueueManager.drainQueue](file:///d:/Parth/Projects/CodeSync/src/shared/queue/manager.ts#L173), which executes [reconcileQueue](file:///d:/Parth/Projects/CodeSync/src/shared/queue/manager.ts#L490).
3. **Storage Read**: `reconcileQueue()` reads `STORAGE_KEYS.QUEUE_METADATA` from `StorageService`, querying the underlying shared driver asynchronously.
4. **Crash Detection & Recovery**:
   - Items left in `PROCESSING` whose persistent leases expired during worker downtime are detected.
   - `crashCount` is authoritatively incremented on disk.
   - The item is made eligible for processing again without penalty to `attempts`.
   - In `CRASH-INT-01`, Worker B executes Step 6 pre-flight GET, encounters 404, performs 1 optimistic PUT, confirms via verification GET, and marks `COMPLETED`.
   - In `CRASH-INT-02` and `CRASH-INT-03`, Worker B executes Step 6 pre-flight GET, detects matching content hash already on GitHub, suppresses redundant PUTs, and finalizes the item as `SKIPPED`.
   - In `CRASH-INT-04`, Worker B reads `nextRetryAt` from durable metadata, skips processing during early startup drain, and only dispatches when virtual time advances past the 429 reset deadline.
   - In `CRASH-INT-05`, Worker B acquires fencing token `N+1`, superseding Worker A's token `N` and blocking Worker A upon resume via [StaleLeaseError](file:///d:/Parth/Projects/CodeSync/src/shared/errors/index.ts).
