## 7. Security Boundary Audit

### 7.1 DOM / Webpage $\rightarrow$ Content Script
- **Context Isolation**: Content script runs in an isolated world (`matches` allowlist restricted to official platform domains).
- **Untrusted Input**: DOM properties, window events, and user scripts are treated as hostile.
- **Candidate Data**: Extraction produces a candidate object (`CanonicalSubmissionCandidate`), not an authorized action.
- **Deduplication**: In-memory `SubmissionEventDeduplicator` suppresses duplicate rapid click/DOM events before messaging.

### 7.2 Content Script $\rightarrow$ Background Service Worker
- **Message Envelope**: [MessageEnvelopeValidator](file:///d:/Parth/Projects/CodeSync/src/shared/messaging/validator.ts#L36) validates envelope structure, UUID v4 nonce, and timestamp freshness.
- **Anti-Replay**: An in-memory sliding-window cache prevents replay of previously seen nonces.
- **Sender Context Verification**: Enforces that `senderContext === "content-script"`.
- **Origin Validation**: [validatePlatformOrigin](file:///d:/Parth/Projects/CodeSync/src/shared/adapters/validator.ts#L35) cross-references `sender.tab.url` with the adapter’s approved origin list. A spoofed message from an arbitrary web page is rejected immediately (`SecurityError`).
- **ValidatedBy Stamp**: The service worker applies `validatedBy = "SERVICE_WORKER"` to the normalized queue model.

### 7.3 Service Worker $\rightarrow$ Durable Queue
- **Validation Authority**: Only the service worker can enqueue items. Content scripts have no direct access to `IndexedDB` or `browser.storage.local`.
- **Target Snapshot Locking**: The service worker captures repository identity, branch, base folder, and duplicate policy into an immutable `TargetSnapshot`. Dynamic user configuration changes made *after* enqueue do not mutate queued items.

### 7.4 Queue $\rightarrow$ GitHub Handler
- **Provenance Gate**: [GitHubQueueSyncHandler](file:///d:/Parth/Projects/CodeSync/src/shared/queue/github-handler.ts#L168) verifies `validatedBy === "SERVICE_WORKER"`. If missing or forged, it quarantines the item (`INVARIANT_VIOLATION`).
- **Integrity Gate**: Recalculates `computeContentHash(payload.sourceCode)` and asserts equality with `item.contentHash`. Any tampering results in immediate quarantine.
- **Path Security Gate**: [validateAndCanonicalizePath](file:///d:/Parth/Projects/CodeSync/src/shared/github/path-engine.ts#L193) executes three-pillar validation (URL decode recursion, NFKC normalization, separator canonicalization, traversal checks, DOS device rejection, Git directory protection, ASCII-only segment whitelist, base folder boundary enforcement).

### 7.5 GitHub Handler $\rightarrow$ GitHub REST API
- **HTTPS Enforcement**: API client rejects any non-HTTPS base URL.
- **Zero Token Leakage**: Tokens are managed by [DurableTokenLifecycleManager](file:///d:/Parth/Projects/CodeSync/src/shared/auth/token-lifecycle.ts#L35); tokens are injected directly into request headers and never returned to the caller or logged.
- **Log Redaction**: [redactSensitiveData](file:///d:/Parth/Projects/CodeSync/src/shared/logger/redactor.ts#L86) scrubs Bearer tokens, GitHub token prefixes (`ghu_`, `ghr_`, `ghp_`, `gho_`), cookies, authorization headers, and passwords.

## 8. Idempotency Audit

### CASE A: Same submission ID + same content
- **Detection**: Content script deduplicator suppresses event. If dispatched, `QueueManager.enqueueSubmission` matches Hierarchy 2 (`platform === raw.platform && submissionId === raw.submissionId`) against active items and returns existing item without duplicate enqueue.
- **GitHub**: If already completed and enqueued again, pre-flight GET detects matching remote `contentHash`; duplicate policy `REPLACE_IF_DIFFERENT` returns `skipped_identical`.

### CASE B: Same submission ID + same content after restart
- **Durable State**: State persists across browser restarts.
- **Execution**: On recovery drain, the item is either deduplicated in queue or evaluated against GitHub via pre-flight GET, yielding `skipped_identical`.

### CASE C: Different submission IDs + same content
- **Hierarchy Enforcement**: In [QueueManager.ts:98-102](file:///d:/Parth/Projects/CodeSync/src/shared/queue/manager.ts#L98-L102), different submission IDs are explicitly **not collapsed**, preserving submission identity.
- **GitHub**: First item commits. Second item executes pre-flight GET; remote hash matches. Duplicate policy `REPLACE_IF_DIFFERENT` cleanly returns `skipped_identical` (or creates version `-v2` under `KEEP_ALL`).

### CASE D: Same submission ID + changed content
- **Queue**: If previous item is still active (PENDING/PROCESSING), matched by submission ID.
- **GitHub**: If previous item completed and a revised submission arrives, pre-flight GET detects hash mismatch. Under `REPLACE_IF_DIFFERENT`, it safely updates the file via OCC blob SHA.

### CASE E: Same queue item triggered by alarm + startup simultaneously
- **Mutual Exclusion**: `QueueConcurrencyManager.runExclusively` coordinates execution via Tier 1 Web Locks (`"codesync:queue:drain"`). The second trigger waits or yields cleanly.
- **Lease Fencing**: Only one worker holds the active `fencingToken`. The second worker sees items already transitioned to `PROCESSING` or completed.

### CASE F: Same queue item recovered after worker crash
- **Crash Recovery**: `reconcileInterruptedItems` increments `crashCount` and resets `PROCESSING` $\rightarrow$ `PENDING`.
- **Idempotent Write**: If crash occurred after GitHub PUT succeeded, the subsequent retry's pre-flight GET matches `contentHash`, returning `skipped_identical` without duplicate commit.

### CASE G: Same repository path modified remotely
- **Pre-flight & OCC**: Remote file change updates blob SHA.
- **TOCTOU Protection**: If modified after pre-flight GET, PUT returns HTTP 409 Conflict.
- **Revalidation**: 8-Step Conflict Protocol fetches fresh remote SHA (max 2 passes). If unresolved, escalates safely to `REQUIRES_ATTENTION`. Zero blind overwrites.

- **Rate Limit Delay Enforcement**:
  In [src/shared/queue/manager.ts:515-526](file:///d:/Parth/Projects/CodeSync/src/shared/queue/manager.ts#L515-L526):
  $$\text{effectiveDelay} = \max(\text{backoffDelay}, \text{rateLimitDelay})$$
  $$\text{item.nextRetryAt} = \text{Date.now}() + \text{effectiveDelay}$$
- **Rate Limit Classification**:
  - Primary rate limit: HTTP 429, or HTTP 403 where `x-ratelimit-remaining === 0`.
  - Secondary abuse throttle: HTTP 403 with `Retry-After` header present and `remaining > 0`. Correctly classified as retryable `GitHubRateLimitError`, **not** an authorization failure.
  - Authorization failure: HTTP 403 without rate limit headers. Correctly classified as non-retryable `GITHUB_FORBIDDEN`.
- **Storm Prevention**: Items with `nextRetryAt > Date.now()` are filtered out during queue drain passes. Maximum retry limit is bounded at 5 attempts (`MAX_ATTEMPTS = 5`), after which items are quarantined to `REQUIRES_ATTENTION`.

## 10. Uncertain-Write / Reconciliation Audit

- **The Problem**: A network disconnect or timeout occurs during HTTP PUT dispatch. Did GitHub commit the commit or not?
- **CodeSync Invariant**: `UNKNOWN WRITE != FAILURE` and `UNKNOWN WRITE != SUCCESS`.
- **Implementation**:
  In [GitHubContentsService.synchronizeFile:364-401](file:///d:/Parth/Projects/CodeSync/src/shared/github/contents-service.ts#L364-L401):
  1. On network failure/timeout during PUT, it calls `reconcileUncertainWrite`.
  2. Executes an authoritative cache-busting GET (`cache: "no-store"`).
  3. If remote `contentHash === localContentHash`: Confirms write succeeded; returns status `created` or `updated` with `dispatchStatus: "uncertain"` and `verificationStatus: "CONFIRMED"`.
  4. If remote hash does not match or file does not exist: Throws `GitHubWriteOutcomeUnknownError`.
  5. In [GitHubQueueSyncHandler:540-550](file:///d:/Parth/Projects/CodeSync/src/shared/queue/github-handler.ts#L540-L550), `GitHubWriteOutcomeUnknownError` maps directly to `status: "requires_attention"`.
  6. **Zero Blind Overwrites**: The item is quarantined in `REQUIRES_ATTENTION`. The system never issues a second blind PUT.
