1. **Durable Queue Core is Production-Ready**: [QueueManager](file:///d:/Parth/Projects/CodeSync/src/shared/queue/manager.ts#L34-L603) already implements atomic, fenced queue draining via `drainQueue(triggerSource, handler)`. ## 4. Actual Queue State Machine

The actual state machine is defined by the TypeScript enum [QueueState](file:///d:/Parth/Projects/CodeSync/src/shared/storage/types.ts#L11-L18):
```typescript
export enum QueueState {
  PENDING = "pending",
  PROCESSING = "processing",
  COMPLETED = "completed",
  FAILED = "failed",
  REQUIRES_ATTENTION = "requires_attention",
  SKIPPED = "skipped",
}
```

### State-Transition Table

| Current State | Trigger / Event | Next State | Durable Mutation | Retry Info | Owner / Fencing Requirement |
| :--- | :--- | :--- | :--- | :--- | :--- |
| *(None)* | Valid submission enqueued via WAL | **`PENDING`** | Item added to `codesync:queue`, payload added to IndexedDB. | `attempts = 0`, `crashCount = 0` | Enqueueing service worker; WAL INTENT $\rightarrow$ COMMITTED. |
| **`PENDING`** | Drainer claims item | **`PROCESSING`** | `state = "processing"`, `fencingToken = token`, `updatedAt = now`. | Unchanged | Active worker holds Web Lock + Persistent Lease; `validateFencingToken` checked. |
| **`FAILED`** | Drainer claims item (when `nextRetryAt <= now`) | **`PROCESSING`** | `state = "processing"`, `fencingToken = token`, `updatedAt = now`. | Retains `attempts` count | Active worker holds Web Lock + Persistent Lease; `validateFencingToken` checked. |
| **`PROCESSING`** | Worker/browser crash during drain | **`PENDING`** | `crashCount += 1`, `state = "pending"`, `updatedAt = now`. | Retains `attempts` count | Executed by recovering worker during `reconcileInterruptedItems()`. |
| **`PROCESSING`** | Worker crash with `crashCount >= 3` | **`REQUIRES_ATTENTION`** | `crashCount += 1`, `state = "requires_attention"`, `lastError = POISON_PILL_DETECTED`. | Terminal; retries halted | Executed by recovering worker during `reconcileInterruptedItems()`. |
| **`PROCESSING`** | IndexedDB payload missing | **`REQUIRES_ATTENTION`** | `state = "requires_attention"`, `lastError = PAYLOAD_NOT_FOUND`. | Terminal; retries halted | Verified active worker; `validateFencingToken` checked. |
| **`PROCESSING`** | GitHub sync returns `completed` | **`COMPLETED`** | `state = "completed"`, `commitSha`, `commitUrl`, `completedAt = now`. Sync history entry created. | Terminal success | Verified active worker; `validateFencingToken` checked. |
| **`PROCESSING`** | GitHub sync returns `skipped` | **`SKIPPED`** | `state = "skipped"`, `completedAt = now`. Sync history entry created. | Terminal no-op | Verified active worker; `validateFencingToken` checked. |
| **`PROCESSING`** | GitHub sync returns `failed` (`attempts < 5`) | **`FAILED`** | `attempts += 1`, `state = "failed"`, `lastError`, `nextRetryAt = now + delay`. | Exponential backoff with $\pm20\%$ jitter | Verified active worker; `validateFencingToken` checked. |
| **`PROCESSING`** | GitHub sync returns `failed` (`attempts >= 5`) | **`REQUIRES_ATTENTION`** | `attempts += 1`, `state = "requires_attention"`, `lastError`. | Terminal exhaustion | Verified active worker; `validateFencingToken` checked. |
| **`PROCESSING`** | GitHub sync returns `requires_attention` | **`REQUIRES_ATTENTION`** | `state = "requires_attention"`, `lastError`. | Requires manual user resolution | Verified active worker; `validateFencingToken` checked. |
| **`PROCESSING`** | Handler throws unhandled exception | **`FAILED`** or **`REQUIRES_ATTENTION`** | `attempts += 1`, `state = attempts >= 5 ? REQUIRES_ATTENTION : FAILED`, `lastError`. | Backoff or terminal | Verified active worker; `validateFencingToken` checked. |
| **`COMPLETED`** / **`SKIPPED`** | Retention window expired ($>24\text{ hr}$) | *(Purged)* | Item deleted from `codesync:queue`, payload deleted from IndexedDB. | None | Background maintenance task via `purgeCompleted()`. |

## 5. WAL Contract

Write-Ahead Logging is implemented in [QueueManager](file:///d:/Parth/Projects/CodeSync/src/shared/queue/manager.ts#L50-L245) and persisted in IndexedDB object store `"wal_logs"` via [PayloadStorage](file:///d:/Parth/Projects/CodeSync/src/shared/storage/indexeddb.ts#L274-L380).

### 5.1 WAL Record Structure ([WalEntry](file:///d:/Parth/Projects/CodeSync/src/shared/storage/types.ts#L157-L174))
* `id: string`: `wal:<uuid>`.
* `operationType: WalOperationType`: `"ENQUEUE_SUBMISSION" | "PURGE_QUEUE" | "STATE_TRANSITION"`.
* `entityId: string`: Item ID being mutated.
* `payloadId: string`: Associated payload ID (`payload:<uuid>`).
* `intendedState: QueueState`: Target state intended by operation.
* `phase: WalPhase`: `"intent" | "mutating" | "committed" | "rolled_back"`.
* `createdAt: number`, `updatedAt: number`.
* `snapshot?: { submission?: NormalizedSubmission; previousState?: QueueState }`.

### 5.2 WAL Protocol Steps
1. **INTENT**: Write `WalEntry` with `phase = WalPhase.INTENT` and submission snapshot to IndexedDB `"wal_logs"`.
2. **PAYLOAD**: Persist `QueueItemPayload` to IndexedDB `"payloads"`.
3. **METADATA**: Read current `codesync:queue` from `browser.storage.local`, append new `QueueItemMetadata`, write back.
4. **COMMITTED**: Update `WalEntry` with `phase = WalPhase.COMMITTED`.
5. **CLEANUP**: Delete `WalEntry` from IndexedDB `"wal_logs"`.

### 5.3 WAL Crash Recovery Protocol
Invoked automatically at the start of `drainQueue()` via `reconcileWalAndOrphans()`:
* **Uncommitted WAL with INTENT**: If metadata exists in `codesync:queue`, promote WAL to COMMITTED and delete WAL log. If metadata does not exist, rollback by deleting the orphaned IndexedDB payload and WAL log.
* **Committed WAL**: If metadata is missing in `codesync:queue`, restore metadata from WAL snapshot and delete WAL log.
* **Orphan Payloads**: Any payload in IndexedDB lacking metadata is indexed into the queue as a recovered orphan.
* **Orphan Metadata**: Any item in `codesync:queue` missing its IndexedDB payload is quarantined to `REQUIRES_ATTENTION`.

## 6. Claim / Lease / Fencing Contract

Two-tier concurrency and fencing control is implemented in [QueueConcurrencyManager](file:///d:/Parth/Projects/CodeSync/src/shared/queue/concurrency.ts#L21-L261).

```mermaid
flowchart TD
    A[Drain Trigger] --> B{Web Locks API Available?}
    B -- Yes --> C[navigator.locks.request 'codesync_queue_drain']
    B -- No --> D[Direct to Persistent Lease]
    C --> D
    D --> E[Read Existing Lease 'codesync:queue_lease']
    E --> F{Active & Owned by Other?}
    F -- Yes --> G[Yield Immediately / Return Null]
    F -- No --> H[Probe-and-Verify Candidate Lease<br/>fencingToken = existing + 1]
    H --> I{Read-Back Matches Candidate?}
    I -- No --> J[Lease Collision Detected / Yield]
    I -- Yes --> K[Lease Acquired Authoritatively]
    K --> L[Start Heartbeat Timer (10s)]
    L --> M[Execute Drain Queue Loop]
    M --> N[Before Every State Mutation:<br/>validateFencingToken workerId, token]
    N --> O{Superseded or Expired?}
    O -- Yes --> P[Throw StaleLeaseError Fail-Closed]
    O -- No --> Q[Apply Durable Mutation]
    Q --> R[Finish / Finally]
    R --> S[Clear Heartbeat Timer]
    R --> T[Orderly Release Lease]
```

### 6.1 Two-Tier Architecture
1. **Tier 1 — Web Locks API (`navigator.locks`)**:
   * Lock Name: `"codesync_queue_drain"` ([concurrency.ts:L9](file:///d:/Parth/Projects/CodeSync/src/shared/queue/concurrency.ts#L9)).
   * Mode: `{ mode: "exclusive", ifAvailable: true }`.
   * Purpose: Active mutual exclusion across concurrent execution contexts within the browser runtime. If unavailable, yields immediately (`null`).
2. **Tier 2 — Persistent Storage Lease (`codesync:queue_lease`)**:
   * Stored in: `browser.storage.local`.
   * TTL: `LEASE_TTL_MS = 30_000` (30 seconds) ([concurrency.ts:L6](file:///d:/Parth/Projects/CodeSync/src/shared/queue/concurrency.ts#L6)).
   * Heartbeat: `HEARTBEAT_INTERVAL_MS = 10_000` (10 seconds) ([concurrency.ts:L7](file:///d:/Parth/Projects/CodeSync/src/shared/queue/concurrency.ts#L7)).
   * Maximum Lifetime: `MAX_WORKER_OWNERSHIP_MS = 300_000` (5 minutes) ([concurrency.ts:L8](file:///d:/Parth/Projects/CodeSync/src/shared/queue/concurrency.ts#L8)).
   * Protocol: **Probe-and-Verify** with pre-commit re-verification and post-commit read-back.

### 6.2 Fencing Token Guarantees
* `fencingToken`: Strictly monotonic integer incremented upon every lease acquisition (`existing ? existing.fencingToken + 1 : 1`).
* **Validation**: Before every durable mutation in `drainQueue()`, the manager executes:
  ```typescript
  await this.concurrency.validateFencingToken(workerId, fencingToken);
  ```
* **Stale Worker Rejection**: If `validateFencingToken` observes that the lease record was superseded by a higher fencing token or expired, it throws [StaleLeaseError](file:///d:/Parth/Projects/CodeSync/src/shared/errors/index.ts). The stale worker is aborted fail-closed and prohibited from mutating queue metadata or recording sync history.

## 7. Payload Storage & Integrity Contract

Payloads are managed by [PayloadStorage](file:///d:/Parth/Projects/CodeSync/src/shared/storage/indexeddb.ts#L491) backed by IndexedDB database `codesync_db` (version 1) in object store `"payloads"`.

### 7.1 Contract Invariants
1. **Size Boundary**: Enforces strict `MAX_PAYLOAD_SIZE_BYTES = 500 * 1024` (500 KB / 512,000 bytes) ([indexeddb.ts:L6](file:///d:/Parth/Projects/CodeSync/src/shared/storage/indexeddb.ts#L6)). Any payload exceeding 500 KB throws `StorageError(PAYLOAD_TOO_LARGE)`.
2. **Key Hierarchy**: Key format is `payload:<uuid>` matching `item.payloadId`.
3. **Integrity Validation Requirements**:

   * Payload exists in IndexedDB (`payload !== null`). If missing $\rightarrow$ quarantine item to `REQUIRES_ATTENTION`.
   * Payload matches expected queue item (`payload.id === item.payloadId`).
   * Cryptographic integrity: Recomputing `computeContentHash(normalizeSourceCode(payload.sourceCode))` matches `item.contentHash`. If mismatched $\rightarrow$ quarantine item to `REQUIRES_ATTENTION`.

## 9. Authentication / Authorization Contract

The GitHub sync engine communicates outcomes via the discriminated union `GitHubWriteStatus` and structured error exceptions:

| GitHub Outcome | Result Representation | Queue Drainer Status Translation |
| :--- | :--- | :--- |

| **Existing File Updated** | `status: "updated"`, `verificationStatus: "CONFIRMED"`, `commitSha` | `SyncResult { status: "completed", commitSha, commitUrl }` |

## 12. Retry / Rate-Limit Contract

### 12.1 Rate Limit Classification ([client.ts:L248-L303](file:///d:/Parth/Projects/CodeSync/src/shared/github/client.ts#L248-L303))
The client extracts rate limits via `extractRateLimit(headers)`:
* **Primary Rate Limit**: HTTP 429, or HTTP 403 where `x-ratelimit-remaining === 0`. Resets at `x-ratelimit-reset` timestamp.
* **Secondary Rate Limit**: HTTP 403 where `Retry-After` header is present and remaining $> 0$ (GitHub anti-spam / abuse detection throttle). **This is NOT an authorization failure.**
* **Authorization Failure**: HTTP 403 without rate limit headers $\rightarrow$ `GITHUB_FORBIDDEN`.

### 12.2 Retry Mechanics
* Delay computed via `computeBackoffDelay(attempt)` ([backoff.ts](file:///d:/Parth/Projects/CodeSync/src/shared/queue/backoff.ts)):
  $$\text{Delay} = \min\left(2000 \times 2^{\text{attempt}-1}, 120000\right) \pm 20\% \text{ jitter}$$
* Maximum attempts: 5. Attempt 5 failure transitions item to `REQUIRES_ATTENTION`.
* Rate Limit Alignment: If `GitHubRateLimitError` provides `resetTimestamp`, the retry delay should respect $\max(\text{backoffDelay}, \text{resetTimestamp} - \text{now})$.

## 13. 409 / OCC Contract

Optimistic Concurrency Control is orchestrated in [GitHubContentsService](file:///d:/Parth/Projects/CodeSync/src/shared/github/contents-service.ts#L298-L359):

```mermaid
sequenceDiagram
    participant D as QueueDrainer
    participant S as GitHubContentsService
    participant G as GitHub API
    D->>S: synchronizeFile(options)
    S->>G: PUT /contents/{path} (sha: currentSha)
    G-->>S: HTTP 409 Conflict
    Note over S: Step 9: 409 Protocol (revalidationCount <= 2)
    S->>G: Fresh GET /contents/{path} (bypass cache)
    G-->>S: Remote File (freshSha, remoteContentHash)
    alt Remote Content Hash == Local Content Hash
        S-->>D: status: "skipped_identical"
    else CREATE_ONLY Policy
        S-->>D: status: "skipped_exists"
    else Re-attempt PUT with freshSha
        S->>G: PUT /contents/{path} (sha: freshSha)
        G-->>S: HTTP 200/201 Success
        S-->>D: status: "updated"
    end
```

* **No Blind Retries**: QueueDrainer **never** retries a 409 independently. `GitHubContentsService` owns the 409 protocol.
* **Escalation**: If revalidation passes exceed `MAX_CONFLICT_REVALIDATIONS = 2`, the service safely escalates to `status: "requires_attention"`, `attentionReason: "GITHUB_CONFLICT"`.

## 14. Uncertain Write / Reconciliation Contract

### 14.1 Network Disruptions During PUT
Network drops or timeouts during write dispatch are decoupled from success ([contents-service.ts:L364-L401](file:///d:/Parth/Projects/CodeSync/src/shared/github/contents-service.ts#L364-L401)):
$$\text{Network Completion} \ne \text{Local Mutation Authority}$$
$$\text{Network Success} \ne \text{Proof of Local Mutation Authority}$$

1. If PUT throws a network error / timeout, `GitHubContentsService` calls `reconcileUncertainWrite(owner, repo, branch, targetPath, localContentHash)`:
   * Executes a fresh authoritative `GET /contents/{path}`.
   * If remote content hash matches local content hash $\rightarrow$ write committed successfully! Returns `status: "created"` or `"updated"` with `dispatchStatus: "uncertain"`.
   * If remote content does not match or file is absent $\rightarrow$ throws `GitHubWriteOutcomeUnknownError`.
2. **Zero Blind Retries**: The system **never** re-dispatches a blind PUT following a network failure.

### 14.2 Post-Write Verification
After PUT returns HTTP 200/201, Step 10 executes an authoritative `GET /contents/{path}`:
* `CONFIRMED`: Remote hash matches intended local hash $\rightarrow$ Operation successful.
* `MISMATCH`: Remote hash differs (third-party concurrent overwrite) $\rightarrow$ `status: "requires_attention"`, `attentionReason: "GITHUB_VERIFICATION_FAILED"`.
* `UNKNOWN`: Verification GET fails/times out $\rightarrow$ `status: "requires_attention"`, `attentionReason: "GITHUB_RECONCILIATION_REQUIRED"`. Commit and file SHAs are preserved for safe reconciliation.

## 16. Idempotency / Duplicate Contract

CodeSync enforces a strict separation between **Submission Deduplication** and **Repository Write Policy**:

### 16.1 Submission Deduplication (Queue Level)
Managed by [QueueManager.enqueueSubmission](file:///d:/Parth/Projects/CodeSync/src/shared/queue/manager.ts#L83-L118):
1. **Internal Queue ID**: Exact match on `item.id`.
2. **Platform Submission ID**: If both items have `submissionId`, matches strictly on:
   $$\text{platform} + \text{submissionId}$$
   *Two submissions with distinct submission IDs are NEVER collapsed, even if problem slug and code are identical.*
3. **Content Hash Fallback**: Only when `submissionId` is absent on both items:
   $$\text{platform} + \text{problemSlug} + \text{contentHash}$$

### 16.2 Repository Write Policy (GitHub Engine Level)
Managed by [GitHubContentsService](file:///d:/Parth/Projects/CodeSync/src/shared/github/contents-service.ts#L153-L181) via `duplicatePolicy`:
* `REPLACE_IF_DIFFERENT`: Skips write if remote file content hash matches local hash; updates file if content differs.
* `ALWAYS_REPLACE`: Updates remote file even if content is identical.
* `CREATE_ONLY`: Writes only if file does not exist; skips if file already exists.
* `KEEP_ALL`: Generates versioned suffixes (`-v2.ext`, `-v3.ext`, up to `-v10.ext`).

## 19. Required 1C.4.2 Integration Contract

The future `QueueDrainer` coordinator in Phase 1C.4.2.1 must satisfy the following contract:

```typescript
export interface IQueueDrainer {
  /**
   * Coordinates draining eligible items by executing QueueManager.drainQueue
   * with an authoritative GitHubContentsService handler.
   */
  drain(triggerSource: TriggerSource): Promise<DrainSummary | null>;
}
```

### Protocol Steps within Drain Handler
1. **Eligibility**: Handled by `QueueManager` (`PENDING` or `FAILED` with `nextRetryAt <= now`).
2. **Payload Retrieval & Integrity**:
   * Retrieve payload via `payloadStorage.getPayload(item.payloadId)`.
   * Verify payload exists, ID matches, and `computeContentHash(payload.sourceCode) === item.contentHash`.
3. **Target & Path Resolution**:
   * Read `targetSnapshot = item.targetSnapshot`.
   * Parse `owner` and `repo` from `targetSnapshot.targetRepository`.
   * Resolve file path using [path-engine.ts](file:///d:/Parth/Projects/CodeSync/src/shared/github/path-engine.ts) with template or fallback `{basePath}/{platform}/{problemSlug}.{ext}`.
4. **GitHub Invocation**:
   * Call `contentsService.synchronizeFile(options)`.
5. **Result Mapping**:
   * Map `created` / `updated` $\rightarrow$ `SyncResult { status: "completed", commitSha, commitUrl }`.
   * Map `skipped_identical` / `skipped_exists` $\rightarrow$ `SyncResult { status: "skipped" }`.
   * Map `requires_attention` $\rightarrow$ `SyncResult { status: "requires_attention", error }`.
   * Catch `GitHubRateLimitError` $\rightarrow$ `SyncResult { status: "failed", error: { retryable: true } }`.
   * Catch `GitHubApiError(isRetryable)` $\rightarrow$ `SyncResult { status: "failed", error: { retryable: true } }`.
   * Catch non-retryable errors $\rightarrow$ `SyncResult { status: "requires_attention", error: { retryable: false } }`.
