## 3. Scope

This audit conducted a comprehensive, strictly read-only security analysis of all externally reachable protocol surfaces, external trust boundaries, and concurrency-control interfaces:

1. **Webpage / Content Script Interface**: Hostile DOM, malicious scripts, fabricated candidate parameters, and platform extraction contexts across LeetCode, CodeChef, Codeforces, and GeeksforGeeks.
2. **Extension Messaging Protocol**: Service-worker runtime listener, message envelope validation, freshness/anti-replay sliding window, sender-context derivation, and least-privilege action allowlists.
3. **Canonical Model Validation & Normalization**: Safe slug and problem identifier grammars, URL validation, character hygiene, payload limits, and cryptographic SHA-256 content hashing.
4. **Queue Ingestion & Target Snapshot Boundary**: Intent-first Write-Ahead Logging (WAL), hybrid storage split (IndexedDB / `chrome.storage.local`), active queue capacity limits, and immutable target configuration capture.
5. **Worker Fencing & Drain Concurrency**: Two-tier concurrency coordination (Web Locks + persistent lease heartbeats), monotonic fencing tokens, and stale-worker completion guards.
6. **Three-Pillar Path Engine**: Bounded recursive URL decoding, ASCII whitelist enforcement, absolute/drive/UNC path rejection, directory traversal guards, DOS device blocking, and base-folder containment.
7. **GitHub Protocol & Transactional Write Engine**: Remote repository/branch validation, pre-flight GET content comparison, duplicate policy enforcement, Optimistic Concurrency Control (OCC) PUT, 8-step 409 conflict resolution, post-write three-way verification, and uncertain write outcome reconciliation.
8. **Auth & Token Lifecycle Protocol**: OAuth Device Flow, token storage, and multi-worker refresh coordination.

## 5. External Attack Surface

The externally controllable inputs and protocol attack vectors reviewed include:
- **Webpage DOM & Events**: Manipulated problem slugs, titles, submission statuses, languages, and source code.
- **Runtime Message Envelopes**: Spoofed UUIDs, future/past timestamps, replayed IDs, forged `senderContext` values, and unauthorized message action types.
- **Origin & Platform Attribution**: Subdomain lookalikes, credential-embedded URLs, unauthorized schemes, and cross-platform origin pairing.
- **Payload & File Content**: Over-sized payloads (>500 KB), forbidden control characters, and post-enqueue payload tampering.
- **File System & Repository Paths**: Traversal sequences (`../`), Windows drive prefixes (`C:`), UNC shares (`//server/share`), DOS reserved device names (`CON`, `PRN`, `AUX`, `NUL`), Git reserved paths (`.git`, `.github`), non-ASCII homoglyphs, and double URL encoding.
- **Remote GitHub HTTP Semantics**: Server errors (5xx), explicit rate limits (429 / 403), authorization revocation (403 Forbidden), optimistic concurrency conflicts (409 Conflict), network dropouts during write dispatch (uncertain writes), and post-write verification hash mismatches.
- **Concurrency & Timing**: Stale worker race conditions, lease TTL expirations, superseded fencing tokens, and worker crash/recovery boundaries.

## 6. Security Invariant Review

| Invariant | Description | Status | Evidence |
|---|---|---|---|
| **I-01** | `WEBPAGE != TRUSTED` | Preserved | Content script runs in isolated world; DOM scraping produces only candidate models; service worker performs independent validation. |
| **I-02** | `CONTENT SCRIPT != TRUSTED` | Preserved | Content script candidates marked `SEMI_TRUSTED`; all fields strictly validated and sanitized in service worker before queueing. |
| **I-03** | Runtime sender context comes from runtime metadata | Preserved | `deriveTrustedSenderContext` uses `runtimeSender.tab` and extension URL metadata. Body-level claims rejected if mismatched (`SEC-INT-01`). |
| **I-04** | `validatedBy` is internally authoritative | Preserved | Value is hardcoded to `"SERVICE_WORKER"` upon validation; `GitHubQueueSyncHandler` rejects items lacking authoritative stamp. |
| **I-05** | Submission identity != Content identity | Preserved | Submission identity is UUID/platform-submission-id; Content identity is cryptographic SHA-256 of normalized code. Evaluated independently. |
| **I-06** | `TargetSnapshot` is immutable | Preserved | Snapshot frozen at enqueue time (`Object.freeze`); handler never falls back to mutable user settings during drain. |
| **I-07** | Local target configuration != GitHub authorization | Preserved | Remote repository GET performed prior to write; HTTP 403 halts sync fail-closed without retry or fallback (`SEC-INT-03`). |
| **I-08** | Payload hash must match authoritative queue metadata | Preserved | `GitHubQueueSyncHandler` recalculates SHA-256 of payload before invoking GitHub; mismatches quarantined to `REQUIRES_ATTENTION` (`SEC-INT-02`). |
| **I-09** | WAL is intent-first | Preserved | `WalPhase.INTENT` written to IndexedDB before any metadata or payload persistence occurs (`QueueManager.enqueueSubmission`). |
| **I-10** | Recovery is idempotent | Preserved | `reconcileWalAndOrphans` safely resolves dangling WAL entries, recovers orphan payloads into quarantine, and never duplicates writes. |
| **I-11** | Fencing precedes durable worker mutation | Preserved | `validateFencingToken` verified before claiming items and before committing outcomes in `drainQueue`. |
| **I-12** | Stale workers cannot commit | Preserved | Workers with superseded or expired fencing tokens throw `StaleLeaseError` fail-closed (`SEC-INT-05`). |
| **I-13** | Path validation is bounded and fail-closed | Preserved | 8-step pipeline enforces ASCII safe grammar, bounded length/depth, blocks traversal, UNC, drive, and DOS device names (`SEC-INT-04`). |
| **I-14** | OCC protects remote writes | Preserved | Pre-flight GET retrieves authoritative blob SHA; SHA supplied in PUT request; concurrent writes fail with 409. |
| **I-15** | 409 requires fresh revalidation | Preserved | `GitHubContentsService` performs up to 2 fresh GET revalidation passes to check duplicate policy before retrying with fresh SHA. |
| **I-16** | Uncertain writes cannot be blindly retried | Preserved | Network drops during PUT dispatch trigger `reconcileUncertainWrite`; unverified writes quarantined to `REQUIRES_ATTENTION`. |
| **I-17** | Verification follows writes | Preserved | Post-write verification GET executed; confirmed hash match required; mismatches quarantined to `REQUIRES_ATTENTION`. |
| **I-18** | Remote authorization failures cannot become retries/fallbacks | Preserved | HTTP 403 is classified as `GITHUB_FORBIDDEN` and moves item to `REQUIRES_ATTENTION`; no retry scheduled. |
| **I-19** | Retry/rate-limit state survives worker restart | Preserved | `nextRetryAt` and `attempts` stored durably in `QueueItemMetadata` in `storage.local`. |
| **I-20** | No unsafe fallback target/path/branch/credential | Preserved | All targets, branches, credentials, and paths are explicit; zero automatic fallback substitutions exist. |
| **I-21** | Security failures fail closed | Preserved | Any validation, integrity, or protocol failure transitions items to `REQUIRES_ATTENTION` or rejects immediately. |
| **I-22** | Manifest permissions remain minimal | Preserved | Minimal MV3 permissions: `storage`, `alarms`; specific GitHub host permissions; zero broad permissions. |

## 13. Security Conclusion

CodeSync's externally reachable protocol boundaries maintain:
- **Fail-Closed Behavior**: Every validation error, signature mismatch, permission revocation, or network ambiguity halts processing without side effects.
- **Least Privilege**: Manifest permissions are minimal (`storage`, `alarms`, specific GitHub origins); content scripts have no access to storage or external network APIs.
- **Trust Separation**: Webpages and content scripts are treated as untrusted/semi-trusted; service worker is the sole validation authority.
- **Payload & Target Integrity**: Payloads are protected by pre-network SHA-256 verification; targets are locked in immutable snapshots.
- **Concurrency & Fencing**: Two-tier concurrency coordination and monotonic fencing tokens guarantee stale workers cannot mutate state.
- **OCC & Recovery Safety**: Optimistic Concurrency Control, 409 revalidation, and post-write verification prevent remote overwrites; recovery from crashes is strictly idempotent.
- **Path Safety**: Conservative POSIX ASCII path engine eliminates path traversal, homoglyphs, and DOS device vulnerabilities.
