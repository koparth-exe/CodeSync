# CODE SYNC — PHASE 1C.4.3.1 CORRECTION REPORT
## P2 Rate-Limit / Uncertain-Write Classification Hardening

---

## 1. Root Cause

In [`src/shared/errors/index.ts`](file:///d:/Parth/Projects/CodeSync/src/shared/errors/index.ts#L294), `GitHubRateLimitError` inherits from `GitHubApiError` and explicitly sets `isRetryable: true`.

In [`src/shared/github/contents-service.ts`](file:///d:/Parth/Projects/CodeSync/src/shared/github/contents-service.ts#L364), the write loop in `synchronizeFile` caught errors from `this.client.createOrUpdateFile(...)` and evaluated:

```typescript
if (
  err instanceof GitHubApiError &&
  (err.isRetryable ||
    err.message.includes("timed out") ||
    err.message.includes("Network failure"))
) {
  // Reconcile before assuming write failed
  const reconciled = await this.reconcileUncertainWrite(
    owner,
    repo,
    branch,
    targetPath,
    localContentHash,
  );
  ...
  throw new GitHubWriteOutcomeUnknownError(...);
}
```

Because `err instanceof GitHubApiError` and `err.isRetryable === true` both held true for `GitHubRateLimitError`, an explicit **HTTP 429** received during a `PUT` request was misclassified as an uncertain write. Consequently:
1. It invoked `this.reconcileUncertainWrite(...)`, issuing an unnecessary post-write `GET` request.
2. When reconciliation established the write did not commit (as expected for a 429), it threw `GitHubWriteOutcomeUnknownError`.
3. In [`src/shared/queue/github-handler.ts`](file:///d:/Parth/Projects/CodeSync/src/shared/queue/github-handler.ts#L540), `GitHubWriteOutcomeUnknownError` forced the queue item into `status: "requires_attention"` with `retryable: false`.
4. This bypassed the dedicated `if (err instanceof GitHubRateLimitError)` catch block in `GitHubQueueSyncHandler`, quarantined the item permanently, and ignored the server's `Retry-After` / `resetTimestamp` backoff instruction.

---

## 2. Correction

A surgical classification check was added directly preceding the Step 11 uncertain-write handler in [`src/shared/github/contents-service.ts`](file:///d:/Parth/Projects/CodeSync/src/shared/github/contents-service.ts#L363-L371):

```typescript
// --------------------------------------------------------------------
// Explicit Rate-Limit Handling (HTTP 429 / 403 secondary)
// --------------------------------------------------------------------
// If the error is an explicit HTTP rate limit, the outcome is authoritatively
// known: the write was rejected and did NOT commit. Bubble immediately so
// QueueManager can schedule a retry with the server-dictated Retry-After delay.
// MUST NOT be treated as an uncertain write outcome or trigger reconciliation.
if (err instanceof GitHubRateLimitError) {
  throw err;
}
```

This preserves the fundamental invariant:
$$\mathbf{HTTP\ Response\ (Known\ Rejection)} \neq \mathbf{Transport\ Failure\ (Outcome\ Uncertain)}$$

1. **Explicit HTTP 429**: Re-thrown immediately. `GitHubQueueSyncHandler` catches it, sets `status: "failed"`, `retryable: true`, and propagates `resetTimestamp` / `retryAfterSeconds`. `QueueManager` calculates `effectiveDelay = max(backoffDelay, rateLimitDelay)` and schedules `item.nextRetryAt`.
2. **Network / Socket Drop / Timeout during PUT**: Does not match `GitHubRateLimitError`. Falls through to `reconcileUncertainWrite(...)` to inspect remote state safely.

## 7. Security & Invariant Verification

1. **Zero Blind Retries**: When an HTTP 429 is received, CodeSync does not assume the write outcome was unknown. It knows with certainty that GitHub rejected the write request before creating a commit. The scheduled retry is a standard idempotent re-attempt of the pending queue item, preceded by normal pre-flight OCC validation (`GET_REPOSITORY`, `GET_BRANCH`, `GET_FILE`).
2. **OCC Protection Intact**: If a concurrent write committed during the rate-limit backoff window, the retried attempt’s pre-flight `GET_FILE` detects the new remote SHA or matching content hash, triggering duplicate policy resolution or OCC conflict handling rather than an overwrite.
3. **Uncertain-Write Safety Preserved**: As proven by `UNCERTAIN-PUT-REGRESSION-01`, socket drops and transport failures on `PUT` continue to invoke `reconcileUncertainWrite`. Rate-limit exclusion is restricted strictly to `GitHubRateLimitError`.
4. **Zero Secret Leakage**: Rate-limit error payloads and queue records store only timestamps, attempt counts, and standard HTTP error codes. Tokens and credentials remain strictly scrubbed.
