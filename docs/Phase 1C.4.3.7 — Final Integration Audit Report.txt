## 7. Authentication Integration

- **Device Flow**: Public client OAuth without embedded client secrets. Verified state machine (`UNCONFIGURED` -> `AUTHORIZING` -> `AUTHORIZED` -> `ERROR`).
- **Credential Lifecycle**: Token expiry checked before every remote call with a 5-minute preflight buffer.
- **Refresh & Generation**: `refreshGeneration` counter increments monotonically. Single-object atomic CAS in `browser.storage.local` under `codesync:auth`.
- **Force Refresh**: A 401 response initiates exactly one forced refresh attempt. If credentials fail refresh or return a second consecutive 401, execution fails closed with `GitHubAuthError`.
- **Fencing & Restart**: Superseded workers holding older `refreshGeneration` cannot overwrite newer tokens. Auth state survives cold restart cleanly.
- **Result**: `VERIFIED`

## 10. GitHub Write Protocol

- **Protocol Sequence**:
  1. Authorization verified via `TokenLifecycleManager`.
  2. Target repository (`owner/repo`) and branch format validated.
  3. POSIX-safe file path validated via `PathSecurityValidator`.
  4. Preflight GET fetches remote blob SHA and content.
  5. Policy evaluated (`EXISTS_IDENTICAL` skips PUT; `KEEP_ALL` searches collision-free candidate 1..100).
  6. Conditional PUT executed with `sha: remoteSha` (Optimistic Concurrency Control).
  7. 409 Conflict triggers fresh GET revalidation (bounded to 3 attempts).
  8. Transport disruptions raise `GitHubWriteOutcomeUnknownError` for reconciliation before retry.
- **Result**: `VERIFIED`
