## 10. Uncertain Write Audit

### Architectural Invariant
$$\text{KNOWN HTTP OUTCOME} \neq \text{TRANSPORT UNCERTAINTY}$$

- When GitHub returns an explicit HTTP response (e.g., 401, 403, 404, 409, 429), the write outcome is known: the write did **NOT** commit. Reconciliation is bypassed entirely.
- When network disconnects, times out, or throws a transport error during `PUT`, the outcome is genuinely uncertain. `reconcileUncertainWrite()` issues an authoritative fresh `GET`:
  - If content hash matches $\to$ `COMPLETED`.
  - If content hash does not match or is absent $\to$ `REQUIRES_ATTENTION` (`GITHUB_WRITE_OUTCOME_UNKNOWN`).
- **Status**: **GREEN**. Fully verified in `PUT-429-01`, `UNCERTAIN-PUT-REGRESSION-01`, and `E2E-08`.

## 11. Verification Failure Audit

### Three-Way Verification Protocol ([src/shared/github/contents-service.ts:215-282](file:///d:/Parth/Projects/CodeSync/src/shared/github/contents-service.ts#L215-L282))
1. **`CONFIRMED`**: Remote content blob hash matches local content hash $\to$ `status: "created" | "updated"`, commit SHA recorded $\to$ Queue item `COMPLETED`.
2. **`MISMATCH`**: Remote file exists but content hash differs (concurrent foreign commit displaced write) $\to$ `status: "requires_attention"`, `attentionReason: "GITHUB_VERIFICATION_FAILED"`, preserving commit SHA $\to$ Queue item `REQUIRES_ATTENTION`.
3. **`UNKNOWN`**: Verification `GET` fails due to network drop or timeout $\to$ `status: "requires_attention"`, `attentionReason: "GITHUB_RECONCILIATION_REQUIRED"`, preserving commit SHA $\to$ Queue item `REQUIRES_ATTENTION`.

### Gap Analysis
`UNKNOWN` is verified in `E2E-08C`. `MISMATCH` is only verified in component tests (`github-contents-write.test.ts:1002`) and lacks an unbroken pipeline test.

## 16. Candidate 1C.4.3.3.1 Tests

To close the remaining evidence gaps without redundant testing, Phase 1C.4.3.3.1 should implement exclusively these **six targeted integration tests**:

### 1. `FAIL-MAT-01`: 401 Unauthorized $\to$ Coordinated Refresh $\to$ Retry Success
- **Purpose**: Verify unbroken pipeline recovery when initial GitHub request receives 401, triggers coordinated token refresh, and retries with new token to `COMPLETED`.
- **Injection Point**: `MockGitHubServer` returns HTTP 401 on first call; returns 200 on retry with rotated token.
- **Expected Outcome**: Queue item transitions to `COMPLETED`, commit SHA recorded, exactly 1 refresh executed, sync history entry created.
- **Why Needed**: Proves `GitHubApiClient` 401 retry loop integrates with queue drainer.

### 2. `FAIL-MAT-02`: 401 Unauthorized $\to$ Refresh Token Revoked $\to$ Quarantine
- **Purpose**: Verify fail-closed quarantine when 401 refresh attempt is rejected by GitHub (`bad_refresh_token`).
- **Injection Point**: Simulated refresh failure in token supplier / auth manager.
- **Expected Outcome**: Queue item transitions to `REQUIRES_ATTENTION` with `code: GITHUB_AUTH_REQUIRED`, `attempts` = 0 (no retry storm).
- **Why Needed**: Proves permanent authentication loss does not trigger infinite retries.

### 3. `FAIL-MAT-03`: 403 Authorization Denial $\to$ Immediate Quarantine
- **Purpose**: Verify non-rate-limit 403 (push access denied / repository read-only) is recognized as authorization failure and quarantined immediately.
- **Injection Point**: `MockGitHubServer` returns HTTP 403 with `x-ratelimit-remaining: 5000` (no `Retry-After`).
- **Expected Outcome**: Queue item transitions to `REQUIRES_ATTENTION` with `code: GITHUB_FORBIDDEN`, `attempts` = 0, zero blind retries.
- **Why Needed**: Proves permission denial is never misclassified as a rate limit.

### 4. `FAIL-MAT-04`: Pre-flight GET Transport Disconnect $\to$ Clean Backoff
- **Purpose**: Verify network failure during pre-flight GET (`GET_REPOSITORY` or pre-flight `GET_FILE`) is handled cleanly without uncertain-write reconciliation.
- **Injection Point**: `MockGitHubServer.configureNetworkFailure({ method: "GET" })`.
- **Expected Outcome**: Queue item transitions to `FAILED`, `attempts` = 1, `nextRetryAt` set via exponential backoff, zero PUT calls, zero reconciliation calls.
- **Why Needed**: Proves clean separation of pre-write transport failure from post-write uncertainty.

### 5. `FAIL-MAT-05`: Post-Write Verification Content Mismatch $\to$ Quarantine
- **Purpose**: Verify that when PUT succeeds but post-write verification GET reveals a different content hash (`MISMATCH`), the item transitions safely to `REQUIRES_ATTENTION`.
- **Injection Point**: `MockGitHubServer.configureVerificationHook({ type: "mismatch" })`.
- **Expected Outcome**: Queue item transitions to `REQUIRES_ATTENTION` with `attentionReason: GITHUB_VERIFICATION_FAILED`, PUT commit SHA preserved for diagnostics, zero duplicate PUTs.
- **Why Needed**: Closes the missing verification outcome path in the E2E pipeline.

### 6. `FAIL-MAT-06`: Pre-flight GET 5xx Server Error $\to$ Retryable Failure
- **Purpose**: Verify HTTP 500/502 on pre-flight GET is classified as a retryable API error and safely completes on second drain pass.
- **Injection Point**: `MockGitHubServer` configured to return HTTP 500 once on GET.
- **Expected Outcome**: First drain sets `FAILED` with backoff; second drain after backoff expiry succeeds to `COMPLETED`.
- **Why Needed**: Validates 5xx classification upstream of write dispatch.
