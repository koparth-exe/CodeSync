# CodeSync — Phase 1C.3 Security Corrections Report (C3.1–C3.3)

## C3.1 GFG Selector Correctness

- **Original Issue**: The GeeksforGeeks adapter previously contained the pseudo-selector `button:contains("Submit")`. This is jQuery-specific syntax and invalid when executed by native DOM selector APIs (`querySelector`, `querySelectorAll`, `matches`), risking DOM exceptions or detection failure.
- **Fix**: Replaced with standards-compliant DOM logic in [`src/shared/adapters/geeksforgeeks/geeksforgeeks-adapter.ts`](file:///d:/Parth/Projects/CodeSync/src/shared/adapters/geeksforgeeks/geeksforgeeks-adapter.ts):
  1. Selects candidate interactive elements using valid CSS: `button, [role="button"], input[type="submit"], input[type="button"]`.
  2. Bounded inspection of candidate elements via native DOM properties (`.textContent`, `.value`, and `type="submit"` attribute).
  3. Case-insensitive matching on extension-controlled keywords (`submit`, `problemsolve`).
  4. Scoped to candidate elements without full-document rescans.
- **Tests**: Deterministic regression tests in [`tests/security/platform-geeksforgeeks.test.ts`](file:///d:/Parth/Projects/CodeSync/tests/security/platform-geeksforgeeks.test.ts) verifying submit button detection across standard `<button>`, `[role="button"]`, and `<input type="submit">` elements without non-standard selector syntax.

## C3.2 Source Provenance Model

- **Model Introduced**: Strongly typed `SourceProvenance` enum/union in [`src/shared/adapters/types.ts`](file:///d:/Parth/Projects/CodeSync/src/shared/adapters/types.ts):
  ```typescript
  export type SourceProvenance =
    | 'AUTHORITATIVE_SUBMISSION_SOURCE'
    | 'SUBMISSION_PAGE_SOURCE'
    | 'EDITOR_SOURCE'
    | 'DOM_FALLBACK_SOURCE';
  ```
  `sourceProvenance` is a required field on all `CanonicalSubmissionCandidate` instances and is verified by fail-closed service-worker schema validation ([`src/shared/adapters/validator.ts`](file:///d:/Parth/Projects/CodeSync/src/shared/adapters/validator.ts)).

- **Per-Platform Extraction Strategies**:
  - **LeetCode** ([`src/shared/adapters/leetcode/leetcode-adapter.ts`](file:///d:/Parth/Projects/CodeSync/src/shared/adapters/leetcode/leetcode-adapter.ts)): If an authoritative source is provided in `context.authoritativeSource`, returns `AUTHORITATIVE_SUBMISSION_SOURCE`. If extracting from Monaco editor lines (`.view-lines`) or `<textarea>`, explicitly returns `EDITOR_SOURCE`. Generic DOM code blocks return `DOM_FALLBACK_SOURCE`.
  - **Codeforces** ([`src/shared/adapters/codeforces/codeforces-adapter.ts`](file:///d:/Parth/Projects/CodeSync/src/shared/adapters/codeforces/codeforces-adapter.ts)): Explicitly distinguishes authoritative source vs editor textarea (`#sourceCodeTextarea`, `textarea[name="source"]`), returning `EDITOR_SOURCE`.
  - **CodeChef** ([`src/shared/adapters/codechef/codechef-adapter.ts`](file:///d:/Parth/Projects/CodeSync/src/shared/adapters/codechef/codechef-adapter.ts)): Distinguishes authoritative source vs live Monaco/textarea editor, returning `EDITOR_SOURCE`.
  - **GeeksforGeeks** ([`src/shared/adapters/geeksforgeeks/geeksforgeeks-adapter.ts`](file:///d:/Parth/Projects/CodeSync/src/shared/adapters/geeksforgeeks/geeksforgeeks-adapter.ts)): Distinguishes authoritative source vs live ACE editor/textarea, returning `EDITOR_SOURCE`.

- **Authoritative vs Editor vs Fallback Behavior**:
  - **Authoritative**: Platform exposes verified submitted-source representation (e.g., submission response / detail view).
  - **Editor Source**: Extracted from active editor/textarea. **Editor contents are NEVER claimed as authoritative proof of the submitted source.**
  - **DOM Fallback**: Extracted from general fallback DOM containers.
  - **Uncertain/Missing**: Fail-closed rejection. Missing or fabricated provenance cannot bypass validator checks.

- **Exact Security Implications**:
  - Eliminates the race condition where a user edits their buffer immediately after clicking Submit, preventing modified code from being falsely attested as the authoritative submitted solution.
  - Preserves the least-privilege boundary: Content Script = Semi-Trusted, Service Worker = Authoritative. Provenance tracking does not require elevated Chrome permissions (`webRequest`, `tabs`, `cookies`, `scripting`, `<all_urls>`).

- **Tests**: Dedicated deterministic test suite in [`tests/security/platform-provenance.test.ts`](file:///d:/Parth/Projects/CodeSync/tests/security/platform-provenance.test.ts) (10 tests), including:
  1. Authoritative submission source → provenance marked `AUTHORITATIVE_SUBMISSION_SOURCE`.
  2. Live editor extraction → provenance marked `EDITOR_SOURCE`.
  3. Explicit simulation where `submitted source = A` and `current editor source = B`: verifies CodeSync reports B as `EDITOR_SOURCE` and never claims B is authoritative.
  4. Provenance survives canonicalization and normalization.
  5. Missing/fabricated provenance rejected fail-closed by the validator.
  6. Source size and validation bounds remain strictly enforced.
  7. Cross-platform provenance handling verified across LeetCode, CodeChef, Codeforces, and GeeksforGeeks.
