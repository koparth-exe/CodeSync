# CodeSync — Phase 1C.3 Final Security Corrections Report (C3.4–C3.5)

## C3.4 Provenance Authority

### 1. Data-Flow Audit
The end-to-end data flow was audited across all execution boundaries:
```text
Webpage (DOM / Page Scripts) [UNTRUSTED]
  ↓ (No direct access to extension runtime or adapter extractSubmission)
Content Script [SEMI-TRUSTED]
  ↓ (Calls adapter.extractSubmission({ document, window, location, detection }))
Platform Adapter [SEMI-TRUSTED]
  ↓ (extractSource evaluates verified authoritative payload vs DOM extraction)
Canonical Submission Candidate
  ↓ (Dispatched via typed ExtensionMessage with UUID v4 nonce & freshness window)
Background Service Worker [AUTHORITATIVE]
  ↓ (SubmissionHandler authoritatively validates sender tab origin, bounds, schema)
Candidate Accepted as Metadata (NEVER an authorization bypass)
```

### 2. Can Page-Controlled Data Assert Authoritative Provenance?
**NO.** The vulnerability surface where a bare string (`authoritativeSource = "someString"`) or a page-controlled attribute could assert authoritative provenance has been eliminated:
- `content.ts` executes in an isolated world and constructs the `ExtractionContext` directly from native extension references. It never sets `authoritativeSource` from page DOM or page scripts.
- Even if untrusted page scripts alter window properties, inject attributes (`data-authoritative="true"`), or pass a bare string to the adapter, the value is rejected fail-closed and falls back safely to `EDITOR_SOURCE` or `DOM_FALLBACK_SOURCE`.
- A webpage or content script cannot manufacture `AUTHORITATIVE_SUBMISSION_SOURCE`.

### 3. Fix Implemented
1. **Strongly Typed Payload Model**: Introduced [`AuthoritativeSourcePayload`](file:///d:/Parth/Projects/CodeSync/src/shared/adapters/types.ts) in `src/shared/adapters/types.ts`:
   ```typescript
   export interface AuthoritativeSourcePayload {
     readonly code: string;
     readonly authority: 'EXTENSION_INTERNAL';
     readonly token: string;
   }
   ```
2. **Fail-Closed Authority Verification**: Implemented [`validateAuthoritativeSource`](file:///d:/Parth/Projects/CodeSync/src/shared/adapters/validator.ts) in `src/shared/adapters/validator.ts`:
   - Rejects non-objects and bare strings (`typeof input !== 'object'`).
   - Validates that `authority === 'EXTENSION_INTERNAL'` and `token === EXTENSION_AUTHORITY_TOKEN`.
   - Fails closed on any untrusted page flags, missing tokens, or tampered tokens.
3. **Adapter Extraction Integration**: Integrated across all 4 adapters ([`leetcode`](file:///d:/Parth/Projects/CodeSync/src/shared/adapters/leetcode/leetcode-adapter.ts), [`codechef`](file:///d:/Parth/Projects/CodeSync/src/shared/adapters/codechef/codechef-adapter.ts), [`codeforces`](file:///d:/Parth/Projects/CodeSync/src/shared/adapters/codeforces/codeforces-adapter.ts), [`geeksforgeeks`](file:///d:/Parth/Projects/CodeSync/src/shared/adapters/geeksforgeeks/geeksforgeeks-adapter.ts)):
   - Unverified inputs are rejected and safely fall back to `EDITOR_SOURCE` or `DOM_FALLBACK_SOURCE`.
   - Only approved extension-controlled inputs produce `AUTHORITATIVE_SUBMISSION_SOURCE`.
   - `AUTHORITATIVE_SUBMISSION_SOURCE` remains metadata only, never an authorization bypass.

### 4. Tests Added
Expanded [`tests/security/platform-provenance.test.ts`](file:///d:/Parth/Projects/CodeSync/tests/security/platform-provenance.test.ts) (14 tests total):
- Proves normal editor extraction produces `EDITOR_SOURCE`.
- Proves generic fallback container extraction produces `DOM_FALLBACK_SOURCE`.
- Proves bare string `authoritativeSource` cannot manufacture `AUTHORITATIVE_SUBMISSION_SOURCE` and falls back safely.
- Proves page-controlled objects (`authority: "PAGE_SCRIPT"`, `isAuthoritative: true`, tampered tokens) cannot manufacture `AUTHORITATIVE_SUBMISSION_SOURCE`.
- Proves cross-platform enforcement across LeetCode, Codeforces, CodeChef, and GeeksforGeeks.

### 2. Why the Configuration is Intentional
- **`codeforces.net` and `www.codeforces.net`**: Intentionally supported. `codeforces.net` is the official Codeforces mirror deployed by the platform during contests and high-load periods.
- **`m1/m2/m3.codeforces.com`**: Removed from `supportedOrigins`. These subdomains were not included in the manifest content-script matches and represent obsolete or unused mirrors. Removing them ensures zero orphaned origins, eliminating risk of spoofed sender URL checks.
